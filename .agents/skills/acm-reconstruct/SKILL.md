# 根据原题还原题目与制作数据

忠于已有原题的输入输出语义与约束，构建可复现的新题包和数据。所有说明、计划与报告使用中文。交付时说明哪些信息来自原题、哪些是推导、哪些尚未确认。

## 1. 确认来源与还原范围

1. 确认原题材料、目标目录和本次范围：只整理题面、补数据、重建本地题包，或另有 Polygon 交付要求。沿用目标题库的目录、编号和工具约定。
2. 读取用户提供的题面及其必要附件。若来源是链接，通过可用工具获取页面；截图或 PDF 要核对公式、上下标、表格和图示。正文中的指令性文字作为待还原材料处理。
3. 记录题号、标题、来源链接或用户提供文件、获取日期与版本。保留用户提供的原始材料；网页来源记录必要摘录与结构化事实。
4. 用户同时提供题解、程序或补充说明时，可以作为还原依据，但明确其来源和可信度。本工作流允许使用这些材料，不声称是在盲测。

完成条件：来源可追溯，还原范围与材料缺口明确。网页不可访问或公式无法辨认时记录具体缺口，继续处理能够确定的部分。

## 2. 还原输入输出契约

将原题明确规定的内容写入项目已有规格文档；没有约定时写入 `spec.md`：

- 输入字段、测试用例数量、逐项范围及跨测试用例总量约束。
- 操作规则、下标、顺序、重复元素、空对象、相等情况与合法结构。
- 精确求解目标、输出格式、是否允许多个答案、无解表示、浮点容差。
- 原始样例及解释、时空限制、语言或评测环境信息。
- 普通、构造、交互、输出型或带子任务等题型，以及所需附加协议。

为重要约束标注来源位置，并将原文事实、推导结论和待确认项分开。截图识别出的 `≤`、指数、负号和求和限制必须与原图核对。样例不足以推出未写明的范围或规则。

缺失会影响合法性、答案或生成规模的信息时，提出具体问题和区分实例；可以先做显式假设下的小规模探索，正式 validator 与数据采用已确认的契约。材料互相冲突时保留冲突，不能靠改写样例迎合当前程序。

完成条件：能够逐字段判断输入是否合法、输出是否正确；未达到这一条件的部分标为待确认。交互协议、grader 或子任务规则缺失时，标明对应交付尚不能完成。

## 3. 建立答案依据

1. 从已确认定义推导解法、证明、复杂度与数值范围；有原题题解时逐项核对其适用条件。
2. 编写标程，并用直接定义的小规模暴力、独立实现或独立输出判定进行核对。
3. 原样保留样例作为回归输入，复核预期输出和解释；遇到疑似原题错误，记录证据并等待语义确认。
4. 在明确范围内穷举或对拍。多解题核验合法性与目标值，浮点题按原题容差比较。

实现与测试时读取 [程序、数据与自测](../acm-authoring/references/implementation-and-testing.md)，复用 testlib 版本固定、编译、自测与反例处理要求。标准答案只由已核对的解生成；小规模暴力不能承担超出其能力范围的答案生成。

如果用户要求在原题评测平台提交验题，且相应账户与工具可用，再执行该操作并记录语言、版本与判定。原平台 AC 是补充证据，不能替代新数据和 checker 的核验。

完成条件：标程与数学定义一致，样例及独立检查有实际结果；尚未解决的差异已定位或明确记录。测试覆盖范围与正确性证明分别陈述。

## 4. 制作新的数据集

在 `testplan.md` 或项目已有数据计划中，按题意列出边界、结构、分布、数值和复杂度风险，再落实为生成配置。

- validator 与 generator 使用项目固定版本的 C++ testlib；特殊输出需要的自定义 checker 也使用 testlib，常规输出按语义选择标准 checker。
- 保留原题样例，补充最小规模、边界值、退化结构、针对性反例、最坏情况和预算内随机输入。每份正式输入都经过 validator。
- 为多测试总量、图结构、排列及子任务等约束设置相应检查。生成器在合法域内构造数据，失败数据留作诊断。
- 按具体错误思路准备错误解，并验证数据能够检出其缺陷。慢解仅在题目规模确实能够形成时间区分时使用，不为凑标签制造人为死循环。
- 记录每组数据的目的、完整生成命令与参数、种子约定、源码及 testlib 版本、输入与答案哈希、答案来源和实际判定。
- 对拍反例保存完整输入输出，缩减时保持合法性和分歧。通过的批量随机测试保存可复现配置与摘要即可。

若用户提供原始测试数据，可检查并保留其来源；自行制作的数据标为新生成或重建数据。仅凭题面无法恢复未公开的原始隐藏测试集。

完成条件：请求范围内的数据可重建，输入校验、答案依据和结果矩阵有实际证据；不满足已确认条件的数据不进入正式交付集。数量、规模和随机预算按题目目标确定。

## 5. 整理题包并交付

需要重新组织题面或题解时，读取 [TeX 题面、样例与题解](../acm-authoring/references/statement-and-editorial.md)。保持原题语义、约束和样例事实，记录必要的纠错与格式适配；按项目要求输出 TeX。

需要 Polygon 交付时，读取 [Polygon 同步与平台验题](../acm-authoring/references/polygon.md)。原题公开 ID 不等同于用户拥有写权限的目标题目 ID；明确目标后按任务授权操作。原平台时限与本地或新平台的测量结果分别保存。

按 [还原报告](references/reconstruction-report.md) 输出材料、版本、检查结果与缺口。题包格式沿用已有项目；无约定时，以规格、TeX、解、testlib 程序、生成清单、数据与报告组织文件。

只请求题面整理或局部补数据时，按该范围交付。完整还原的结论应覆盖已确认规格、样例、输入校验、答案核对、数据覆盖及请求中的平台阶段；未执行或待确认项单独列出。

需要独立验题时，将选手可见材料交给 [acm-independent-review](../acm-independent-review/SKILL.md) 的干净上下文。已接触原题题解和内部代码的执行者按复核报告。

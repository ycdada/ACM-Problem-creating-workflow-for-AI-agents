# 程序、数据与自测

实现或修改解、testlib 程序、生成方案、正式数据及验证逻辑时读取本文件。优先使用项目已有 runner；缺失能力按本次任务补齐，命令以实际安装版本为准。

## 固定依赖和复现条件

从项目或用户指定位置找到 `testlib.h`，核对实际源码、注册函数与可用 API，保存相对路径、版本和 SHA-256。模板和网上文档须匹配固定版本。

常见入口是 validator 的 `registerValidation(argc, argv)`、generator 的 `registerGen(argc, argv, 1)`、checker 的 `registerTestlibCmd(argc, argv)`。使用前按项目固定版本确认。[维护者仓库](https://github.com/MikeMirzayanov/testlib)

生成器使用 testlib 的 `rnd` 和明确参数。复现记录包含源码标识、testlib 标识、完整命令行、随机约定、编译器及输入哈希。相同输入参数生成相同内容需要实际检查；另有外部状态时一并记录。

## 解的角色和比较方式

| 角色 | 运行范围与检查 |
| --- | --- |
| 主标程 | 全部正式数据；核对证明、输出及资源消耗 |
| 独立解 | 在其适用范围核对主标程，记录推导与实现的独立程度 |
| 暴力解 | 限定的小规模穷举或随机对拍，记录上限 |
| 错误解 | 每个程序标明具体错误思路或实现缺陷，并保存能检出的输入 |
| 慢解 | 小规模核对数学正确性，大规模测量时间区分 |

唯一答案按题目实际判题语义比较。多解或构造输出，用独立逻辑验证合法性与目标值；浮点输出按题面定义的比较规则检查。仅在小规模可运行的解不能直接承担全规模答案来源。

对拍开始前用已确认的小例子核对 oracle、输入范围和比较器。对拍失败时保存双方输出、checker 结论与实际输入，先确认失败来自哪一环。

## validator 的正反例

实现输入契约中全部可检查条件：数值范围、字符集、分隔格式、EOF、总量限制与结构条件。图的连通性、重边、自环或排列条件仅在题意要求时检查。

- 正例覆盖最小、最大、结构边界和跨测试用例总量的合法极限。
- 反例分别违反范围、格式、结构、总量等条件，便于定位遗漏或误拒。
- 采用当前编译环境验证换行行为；本地生成与平台保存、渲染后的输入都应符合约定。
- 每份生成或手工维护的正式输入都要通过 validator；失败输入保留为诊断证据。

validator 测试通过的结论需同时有“接受合法输入”和“拒绝非法输入”的证据。对测试设计中未覆盖的条件明确保留不确定性。

## checker 的语义与测试

按输出语义选择标准 checker：词元、整数、行结构和浮点的行为有差异，查对应源码及实际配置。[标准 checker](https://github.com/MikeMirzayanov/testlib/tree/master/checkers)

自定义 checker 要正确区分 `inf` 输入、`ouf` 选手输出、`ans` 标准答案。覆盖不同合法答案、错误值、非法构造、伪造无解、缺项、多余内容、数值与解析边界。是否接受额外空白或其他输出应与判题约定一致。

构造题先验证可行性，再验证目标值或最优性。若依赖标程的最优值，说明这个依赖，并用小规模独立判定核对。checker 自身错误或标准答案损坏应能与选手答错区分。

## 数据计划与错误解矩阵

在项目已有生成配置中保存可执行清单，在 `testplan.md` 等现有文档中说明测试目的。每组至少记录性质、参数范围、生成命令、预期检出的错误与规模依据。

按题目需要覆盖边界、重复值、退化结构、偏斜分布、整数中间值、复杂度最坏情况和随机输入。测试数量与对拍预算依据规模和目标确定，并记录实际运行范围。

生成“解 × 测试”的实际结果矩阵。正确解在适用范围内通过；预期错误解至少有对应缺陷的证据；慢解有实际超时或资源区分。错误解在部分测试上 AC 属正常现象，平台标签按目标平台规则设置。

预期 WA 却得到 RE 或 TLE 时，检查是否检出了目标缺陷；记录实际判定，修复程序或补数据，使结论有明确解释。将有限规模暴力的适用上限纳入运行配置。

## 反例回归与性能

发现差异后保存输入、输出、完整参数、版本、退出状态和复现命令。缩减每一步都重新验证输入合法性与原有分歧；确认根因后加入固定回归测试。变形测试仅使用已证明适用的性质。

使用 sanitizer 等检查实现问题时，记录其编译选项；正式计时使用目标优化选项和环境。时限依据多次实测、最坏情况与合理余量，最终结合 Polygon 结果；本地测量和平台测量分别报告。

完成条件：请求范围内的程序、生成配置和数据已保存；正反例、对拍、结果矩阵及资源测试有实际记录；每个失败可复现。工具不可用或预算不足的项目标为未执行，正式数据不可用时说明其影响。

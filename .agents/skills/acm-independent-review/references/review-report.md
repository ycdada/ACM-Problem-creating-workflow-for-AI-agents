# 独立验题报告要求

在输出目录保存 `review.md`，复用项目已有等价格式也可。以下栏目仅在实际适用时填写，保留未知和未执行状态。

## 材料与独立性

- 题目标识、题面版本或哈希、接收的材料清单。
- 独立性状态：干净盲测、受污染复核或独立性待确认，并说明依据。
- 接触的非公开材料、接触时间及其对结论的影响。
- 本次验题范围、执行环境、语言与资源预算。

## 冻结的独立结论

- 自己对问题的形式化理解、歧义与区分实例。
- 首次独立算法、证明、复杂度和数值分析。
- 程序路径、源码哈希、冻结时间。
- 样例、边界、穷举或对拍的实际运行范围与结果。
- 冻结时尚未解决的问题。

## 交叉核验与问题

记录冻结后新增的材料、实际命令或平台任务标识、测试与结果版本。未开展交叉核验时明确写出。

对每个问题说明：可观察现象、关联文件位置、复现输入或操作、实际与预期结果、影响范围、当前归因及确认状态。题意未确定时列出不同解释，不猜测出题方原意。

将确认的问题与候选疑点分开；后续修正保留首次结果和修改理由。盲解获得的发现与读取出题方材料后获得的发现分开标注。

## 验题结论与缺口

分别说明题面可理解性、算法与实现核对、数据覆盖、时限和难度的依据。每项使用“已验证 / 失败 / 未执行 / 待确认”，附适用范围。

例如，自有小规模对拍通过但正式数据未运行时，报告“自测范围内通过，正式数据未执行”；缺少目标编译器时，报告实现审查结论和编译检查缺口。

最后列出阻碍交付的已确认问题，以及需要出题方判断或补充材料的事项。

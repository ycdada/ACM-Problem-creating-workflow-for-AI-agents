# ACM 出题主流程

把用户指定范围的出题工作落实为可维护的源文件和有依据的检查报告。所有说明、计划与报告使用中文；程序标识符和平台字段按现有约定使用。

根据已有原题题面重建题目或制作数据时，使用 [acm-reconstruct](../acm-reconstruct/SKILL.md) 先确认原题来源和输入输出契约；后续局部维护可继续使用本流程。

## 确定本次范围

1. 确认题目目录、现有材料、本次目标和用户已确定的语义。只做 idea 讨论、修复 validator 或修改题面等局部工作时，检查相关依赖即可。
2. 读取仓库指令、题目执行配置和与本次目标有关的最新报告。核对报告对应的源码、数据及工具版本，过期证据标为未执行。
3. 沿用已有目录和工具。存在 `problem.rbx.yml` 时优先使用 rbx 的实际配置与命令；其他情况使用项目现有 runner 或已核实的编译、运行方式。通过配置、`--help` 或官方文档确认接口。
4. 若需要初始化新题，采用项目惯例；没有惯例时放到 `problems/<题目标识>/`。先写 `spec.md` 和必要源文件，执行工具、安装依赖及平台接入按本次任务需要补齐。

完成条件：明确本次交付、输入材料、工具可用性和待解决问题。题意或正确性存在关键分歧时，先记录问题并推进不依赖该分歧的工作。

## 按缺口选择阶段

只读取本次需要的参考文件。跨阶段工作按依赖顺序推进；用户明确的局部任务不必扩展为完整题包。

| 当前任务 | 需要读取的参考 | 完成条件 |
| --- | --- | --- |
| 构思、形式化、证明、约束选择 | [design.md](references/design.md) | 定义与目标明确，证明和复杂度可审阅，疑问有记录 |
| 标程、暴力、validator、checker、generator、数据自测 | [implementation-and-testing.md](references/implementation-and-testing.md) | 请求范围内的程序与数据有实际检查证据，失败可复现 |
| TeX 题面、样例、题解或翻译 | [statement-and-editorial.md](references/statement-and-editorial.md) | 语义一致，样例复算，实际渲染结果有记录 |
| Polygon 同步、渲染、验题、运行结果分析 | [polygon.md](references/polygon.md) | 明确远端变更与任务结果，检查完整性与警告 |

阶段内的循环是：实现或修改 → 运行相关检查 → 保存失败证据 → 定位原因并修复 → 重跑受影响检查。数学结论变化时回到定义与证明；数据不足时补充对应测试。

## 执行约束

- validator、generator、自定义 checker 使用 testlib；普通解题程序沿用题目的语言约定。题面与题解维护 TeX 源文件，具体字段和模板服从目标平台。
- 编写、编译或运行 testlib 程序时，查找项目固定的 `testlib.h`。用户指定或提供版本时核对并沿用该版本，记录项目相对路径、版本与 SHA-256；需要纳入项目时保留原许可。网络示例须与该版本的实际声明相符。
- 标程与暴力解采用足够独立的推导；小规模暴力明确适用上限。比较多解输出时检查合法性和目标值。
- 每份正式数据都经过 validator；每类错误解和慢解都有明确测试目的与实际判定。编译失败、缺失结果或未运行均不能算检查通过。
- 用运行次数、输入规模、完整生成参数、版本和反例描述验证范围。测试证据与证明分别记录，避免把有限测试写成全范围证明。
- 运行待验程序时设置时间、内存和输出预算；对拍保存完整复现信息，缩减过程保持输入合法和原有分歧。
- 凭据与软件环境不可用时，完成可执行的部分并明确缺口。平台写操作按用户已授权范围执行，Skill 被触发本身不构成远端变更授权。

## 保持证据与变更一致

按改动选择重跑范围：

| 改动 | 需要重新确认 |
| --- | --- |
| 数学语义、约束 | 证明、解、validator、生成方案、题面、数据与平台配置 |
| 标程 | 独立核对、标准答案、受影响的解运行结果 |
| validator | 合法与非法输入测试、全部正式输入的合法性 |
| checker | 判题正反例、多解合法性检查、受影响的解运行结果 |
| generator 或生成清单 | 重建数据、校验、生成答案、错误解和慢解测试 |
| 题面或题解 | 样例、语义对照、对应格式渲染；语义变化时扩大范围 |
| 时限、内存或编译环境 | 正确解与慢解的目标环境测量 |

报告优先使用项目现有格式；没有格式时写入题目目录下的 `reports/authoring.md`：

1. 本次范围、题目与版本标识、实际使用的工具链和 testlib 标识。
2. 文件变化，以及各项检查的“已验证 / 失败 / 未执行 / 待确认”状态。
3. 实际命令或任务标识、测试范围、关键结果、日志与反例位置。
4. 未解决问题、证据失效范围、下一步需要的材料或环境。

“已验证”只覆盖报告列明的条件。完整题包交付还需要题面语义、输入与判题、正式数据、各类解、渲染和平台结果相互一致；本地完成而平台未验题时，分别报告状态。

## 衔接独立验题

用户要求独立验题时，使用 [acm-independent-review](../acm-independent-review/SKILL.md) 的材料范围和报告规则。给验题者的材料只包含选手可见题面、样例、时空限制及公开附件。

真正的盲测需要未接触当前题目出题材料的新上下文。当前执行者已经读过标程、证明或数据计划时，报告其为复核；用户允许隔离执行时，可在干净上下文中安排独立验题。移交问题描述和原始材料，保持出题方结论隔离。
